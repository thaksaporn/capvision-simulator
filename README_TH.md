# CapVision Machine Lab W1

ดับเบิลคลิก `เปิด_CapVision_Simulator.cmd` เพื่อเปิดเว็บและ Bridge ในเครื่อง จากนั้นกด “เริ่มสาธิตครบวงจร” ใช้ Python 3 ที่มีอยู่แล้ว ไม่ต้องลงชุดเว็บเพิ่มเติม ทุกโมเดลและไลบรารีอยู่ในโฟลเดอร์ ใช้โหมดเว็บได้โดยไม่ต้องใช้อินเทอร์เน็ต

อ่านคู่มือเต็มใน `dist/manual.html` หรือกดวิธีใช้งานจากหน้าเว็บ

## ไฟล์สำคัญ

- `dist/index.html`, `app.mjs`, `style.css`: หน้าควบคุมและ 3D
- `dist/engine.mjs`: ตัวแปลคำสั่ง Ladder B2 และโรงงานจำลองแบบตอบสนองสด
- `dist/assets/machine.glb`: geometry จาก `CapVision_Realistic_C3_Editable_Parts.blend`
- `dist/assets/cap.glb`: geometry ฝาจาก `CapVision_Realistic_C3_Animated.blend`
- `dist/assets/engine.wasm`: แกน C จาก F1 พร้อมค่าระยะสำหรับโมเดลเว็บ
- `bridge/`: Local HTTP bridge + SLMP 3E TCP + MX Component COM adapter
- `PLC/CapVision_B2_GX_Simulator.gx3`: B2 native เดิม 122 แถว สำหรับเปิด GX Simulator3
- `PLC/CapVision_W1_Ladder_IMPORT.csv`: Ladder เต็มที่เพิ่ม Remote mailbox/Heartbeat ต้อง import และ Rebuild ใน GX ก่อนใช้งานจริง
- `tests_engine.mjs`, `tests_bridge.py`, `tests_mailbox.mjs`: การทดสอบที่รันซ้ำได้ พร้อมรายงาน JSON

## สถานะการเชื่อมต่อจริง

เครื่องนี้ยังไม่พบ MX Component COM ที่ใช้เชื่อม GX Simulator3 และผู้ใช้ยังไม่ได้ตั้ง IP/SLMP ของ FX5U จึง **ยังไม่ยืนยันว่าทั้งสองปลายทางเชื่อมต่อได้จริง** Bridge ทดสอบกับ SLMP mock แล้ว เริ่มจากอ่านอย่างเดียว เปิดให้ส่งคำสั่งเมื่อผู้ใช้เปิดรับคำสั่งและผ่านเงื่อนไขที่ PLC กำหนด

ไม่มีการดาวน์โหลด PLC ไม่มีการเปลี่ยน IP และไม่มีการสั่งอุปกรณ์จริงระหว่างพัฒนา W1 mailbox ทดสอบคำสั่งผ่านตัวแปลอิสระ ยังไม่ได้คอมไพล์ด้วย GX โปรเจกต์ .gx3 ที่แนบยังเป็น B2 เดิม

โหมด PLC จริงแสดงข้อมูลที่อ่านได้ ไม่จำลองตำแหน่งฝาจริงหรือยอดผลิตขึ้นเอง เพราะต้องเพิ่มข้อมูลจากบอร์ดและกล้องจริง ส่วนโหมดเว็บ/GX ใช้ผลกล้องจำลองที่ระบุบนจอ

## W2 โหมด "จำลองในเว็บ + รีเจคออก FX5U"

เครื่อง (สายพาน กล้อง ฝา) ยังจำลองและเป็นอนิเมชันในเว็บ ทุกครั้งที่ระบบสั่งรีเจค ไฟแสดงผลจริงที่ FX5U ติดแล้วดับพร้อมกัน (ช่วงนี้ยังไม่ต่อมอเตอร์ / encoder / วาล์ว)

| เหตุการณ์ในเว็บ | Bridge เขียน | Ladder W2 | ขั้วจริง (แบบ E1) |
|---|---|---|---|
| รีเจค A | `M7230` = 1 | ติด 0.5 s แล้วดับ | **Y15** ไฟรีเจค A |
| รีเจค B (สำรอง) | `M7231` = 1 | ติด 0.5 s แล้วดับ | **Y16** ไฟรีเจค B |

Y1/Y2 (วาล์ว YV1/YV2) ถูกล็อก OFF ไว้ในช่วงนี้ · ปรับเวลาติดได้ที่ `OUT T30 K5` / `OUT T31 K5` (K5 = 0.5 s)

Y15/Y16 ติดได้เมื่อครบทุกข้อ (ladder ตรวจเอง ไม่ขึ้นกับเว็บ): `M7190` Remote enable · Heartbeat เว็บ < 500 ms (`M7220`) ·
Hardware arm `M7001`=ON และ `M7000`=OFF — ขาดข้อใดไฟดับทันที · เป็นไฟแสดงผลจึงไม่ผูก Safety X16/X17
(ถ้ากลับไปใช้วาล์วจริง ต้องเปลี่ยนขาออกกลับเป็น Y1/Y2 และใส่ `AND M114` / `AND M115` คืนในวงจรอนุญาต W2)

### ขั้นตอนใช้งานกับ PLC จริง
1. แก้ `PLC/CapVision_W1_Instruction_List.txt` แล้วรัน `python tools/build_ladder.py` (สร้าง JSON + CSV ให้ตรงกัน)
2. นำเข้า `PLC/CapVision_W1_Ladder_IMPORT.csv` ใน GX Works3 → Convert → เขียนลง FX5U (โปรเจกต์ `.gx3` เดิมยังไม่มีวงจร W2)
3. ใน GX Works3: ตั้ง `M7000`=OFF, `M7001`=ON (Hardware arm) และ `M7190`=ON (Remote enable)
4. ต่อไฟแสดงผล 24V ที่ Y15 และ Y16 (COM ของกลุ่ม Y14–Y17 ตามชนิดเอาต์พุตของ PLC)
5. เปิด Bridge → แท็บเชื่อมต่อ → เลือก **จำลองในเว็บ + ไฟรีเจคที่ FX5U (Y15/Y16)** → ใส่ IP PLC / port SLMP → เชื่อมต่อ
6. ติ๊ก **เปิดรับคำสั่งควบคุม** → กด **เริ่มสาธิตครบวงจร**

ทดสอบโดยไม่มี PLC: `python tools/mock_fx5u.py` แล้วเชื่อมต่อที่ 127.0.0.1 กับ port ที่แสดง — จะพิมพ์ `REJECT A -> Y15` ทุกครั้งที่ส่ง

> E-stop/Safety ของเครื่องจริงต้องตัดไฟ +V0 ด้วยฮาร์ดแวร์ ไม่พึ่งเงื่อนไขใน ladder อย่างเดียว · ยังไม่ได้ทดสอบกับ FX5U จริง

## W3 ชุดฝึก FX5U: ปุ่ม X0/X1 ↔ เว็บ (ยังไม่ต่อมอเตอร์ / encoder)

ให้ PLC ถือสถานะ "เดิน/หยุด" ไว้ที่ตัวเดียว (M7235) แล้วให้เว็บทำตาม ทั้งสองฝั่งจึงตรงกันเสมอ

| ขั้ว | อุปกรณ์ | ทำอะไร |
|---|---|---|
| X0 | ปุ่ม START (NO) | กดแล้วเครื่องในเว็บเริ่มเดิน (ป้อนฝาต่อเนื่อง) |
| X1 | ปุ่ม STOP (NO) | กดแล้วเครื่องในเว็บหยุด · กดพร้อม X0 = STOP ชนะ |
| Y5 | ไฟเขียว | เครื่องทำงาน |
| Y6 | ไฟแดง | หยุด |
| Y15 | ไฟ | รีเจค A (ติด 0.5 s แล้วดับ) |
| Y16 | ไฟ | รีเจค B (ติด 0.5 s แล้วดับ) |

**ใช้งาน**
1. นำเข้า `PLC/CapVision_W1_Ladder_IMPORT.csv` → Convert → เขียนลง FX5U
2. ทุกครั้งที่เปิดไฟ PLC: ใน GX Works3 (Device/Buffer Memory Batch Monitor) ตั้ง `M7000`=OFF, `M7001`=ON, `M7190`=ON → ไฟ Y6 จะติด
3. ดับเบิลคลิก `เปิด_Bridge_ใช้กับลิงก์ออนไลน์.cmd` (หรือ `เปิด_CapVision_Simulator.cmd`) → แท็บเชื่อมต่อ → เลือก **จำลองในเว็บ + ชุดฝึก FX5U** → ใส่ IP PLC, port 5000 → เชื่อมต่อ
4. ติ๊ก **เปิดรับคำสั่งควบคุม** → กด X0 ที่ชุดฝึก
5. **เปิดหน้าเว็บค้างไว้ (อย่าย่อหน้าต่าง/สลับแท็บ)** เบราว์เซอร์จะหยุดหน้าที่ไม่แสดง → heartbeat ขาด → PLC หยุดเองและไฟ Y6 ติด (ออกแบบให้ปลอดภัยไว้)

**กรณีที่ระบบจัดการให้แล้ว (มีเทสต์ครบ)**
- กด X0 สั้นแค่รอบสแกนเดียวก็ติด · กด X0 ค้างแล้วกด X1 จะไม่เริ่มเองอีก
- เว็บไม่ได้เชื่อม / ไม่ได้ติ๊กเปิดรับคำสั่ง / ไม่ได้ arm → กด X0 ไม่มีผล ไฟยังเป็น Y6
- ลิงก์เว็บขาดระหว่างเดิน → PLC หยุดเองภายใน 0.6 วินาที
- กด START/STOP ในเว็บก็ได้ ไฟ Y5/Y6 ตามเว็บ · เว็บเริ่มไม่ได้หรือเกิด fault → แจ้ง PLC หยุด ไม่เริ่มใหม่เอง
- หยุดตอนฝากำลังตรวจ → ไม่เกิด fault · กด X0 รอบต่อไปล้างฝาค้างให้อัตโนมัติ

ทดสอบโดยไม่มี PLC: `python tools/mock_fx5u.py` แล้วพิมพ์ `x0` / `x1` + Enter แทนการกดปุ่ม
